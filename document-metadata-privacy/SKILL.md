# 文档元数据隐私

用户偏好：新生成、导出且准备交付的文档，默认按下方“用户指定属性”填写作者和时间，并清除其余非必要软件及编辑历史属性。作者信息来自用户指定；自定义时间不代表真实编辑历史。不虚构软件来源，不承诺“无法识别 AI”或“无痕”。这是文件属性整理，不是来源证明。

## 执行顺序

1. 用适用的文档、演示、表格或 PDF 技能完成内容与版式。新建时按“用户指定属性”填写作者；生成库自动带入的其他作者或软件默认值由交付前步骤处理。
2. 完成最后一次保存和格式转换后，先检查最终文件。若同时交付 DOCX/PPTX/XLSX 和 PDF，两种文件分别处理。只处理本任务交付物，不扫描用户全部文件。
3. 按下方“保留原文件名”流程备份原件，在独立暂存目录生成清理文件；应用“用户指定属性”并完成第4、5步验证后，再以原文件名交付。原件备份与检查报告留在工作目录，不把原属性或日志嵌入交付物，不修改本机审计记录或云端历史，不人为伪造文件系统时间。
4. 查看 `remaining` 和 `before.review_flags`。区分用户指定保留的属性与待清理残留；不要将非空的默认作者和时间误报为清理失败，也不要声称所有属性为空。按[格式与复查说明](references/formats.md)处理批注、修订、演讲者备注、隐藏工作表、嵌入附件及媒体等残留。正文中的 Codex/OpenAI 可能是正常内容，不能全局替换。
5. 重新打开或渲染清理后的文件，按原制作技能检查内容、公式、页数和版式。阅读时不保存；如果软件重新保存、导出或打印为 PDF，重新清理并复查最终文件。
6. 简要说明清理范围；有未解决的复查项就明确列出，不把有残留的文件描述为匿名或彻底清理。没有必要每次重复长篇提醒。

## 用户指定属性

适用于本用户让 Codex 新生成或导出的文档；已有文档按本次请求限定范围修改，只检查时不写入。正文姓名、学号、邮箱空栏不因元数据默认值而填写。

- 作者默认 `19436`，最后修改者默认 `朱文好`；用户当前明确指定值优先。
- 时间以 Asia/Shanghai（北京时间）计算，格式需要时转换成 UTC 存储。修改日期默认取本次操作的北京时间日期；修改时刻在16:00至22:00之间随机生成，创建时刻在14:00至20:00之间独立随机生成。随机到秒，分钟从1至59、秒从1至59取值，避开整点及窗口端点；忽略日期，仅将两个时刻的时分秒换算为自午夜起的秒数，要求绝对差至少10800秒（3小时），不是跨午夜的环形最短距离；不满足时重新抽取。该条件与完整时间戳至少相隔48小时的条件须同时满足。
- 创建日期按内容规模选在修改日期至少2个日历日前：简短文档通常2天；含推导、实验或分析的课程报告通常3天；更长综合文档可选更长间隔。生成后须检查完整时间戳满足“修改时间减创建时间至少48小时”，不能只比较日期；不足48小时则重抽，或将创建日期再提前一天。创建时间必须早于且不等于修改时间。
- 上述随机时刻取代“修改时间必须为实际当前时刻”的旧默认。它们是用户指定的文档属性，可能晚于实际操作时刻，不表示真实编辑历史或创作耗时。交付时报告实际写入的两个北京时间；不据此修改文件系统时间、日志或云端记录。
- 标题元数据、模板名、修订次数和最后打印时间默认清空，正文标题保留；格式支持时总编辑时间可设为0，只作为默认属性，不声称实际耗时为0。
- 制作软件、版本及来源信息不伪造；新生成文档清理非必要的软件属性，用户要求保留实际软件信息时保留。不要复制之前报告中的 WPS 账户标识、ICV 或保存记录。

先清理非必要属性，再以格式原生方法写入指定字段，随后验证并只读检查。`sanitize.py clean` 仍会清空全部目标属性，不会应用上述默认值；写入指定字段后用 inspect 和逐字段核对验证，不再运行 clean 把它们删掉。原脚本不改动。

OOXML 使用 `dc:creator`、`cp:lastModifiedBy`、`dcterms:created`、`dcterms:modified`，时间类型为 W3CDTF。PDF 使用 Author、CreationDate、ModDate，并保持相关 XMP 一致或移除冗余 XMP；PDF无通用的最后修改者或总编辑时间标准字段，不额外创建个人信息字段。其他格式按专用工具支持范围处理，不支持的字段明确报告。签名、加密及符合性限制仍按原规则执行。

## 保留原文件名

默认沿用用户现有的文件名和扩展名，交付文件不添加“元数据清理版”“已清理”等后缀。用户明确指定新名字时按其要求；必须转换格式时保留原主文件名，仅改变扩展名并说明。

- 只要求检查时，执行只读检查，不清理、替换或重命名文档。
- 清理已有交付文件时，先将原文件复制到本任务工作目录的独立备份目录，记录原件哈希。使用另一个独立暂存目录，以相同文件名作为脚本的输出；该输出路径必须尚不存在。备份、暂存和日志均与交付物分开存放。
- 检查残留、内容和版式后，确认交付位置的文件仍与备份哈希一致，再将验证通过的暂存文件替换到原交付路径，保留原件备份。替换失败或文件被占用时保留原件与暂存文件，说明原因；若原文件已被用户修改，重新从最新文件备份和检查，不能覆盖新的编辑。不要先删除原文件。
- 替换后核对最终文件与已验证暂存文件的哈希，并在原交付路径重新执行 inspect；交付链接使用这个原文件名。复制或替换可能自然更新文件系统时间，无需回写伪装。

此流程保留脚本“拒绝覆盖已有输出”的保护，通过独立目录解决同名冲突。用户对本任务的清理授权包括验证后更新同名交付物；仍须遵守实际文件系统权限。

## 脚本

脚本路径相对于本 `SKILL.md`：`scripts/sanitize.py`。需要 Python 3.10+；OOXML 用 `lxml`，PDF 用 `pypdf`（已在 6.10.0 验证）。优先用 `load_workspace_dependencies` 返回的 Python；不要假定系统 Python 装齐依赖。脚本不联网、不上传文档。

```powershell
& '<Python绝对路径>' '<skill绝对路径>/scripts/sanitize.py' inspect '<文件绝对路径>'
& '<Python绝对路径>' '<skill绝对路径>/scripts/sanitize.py' clean '<源文件绝对路径>' --output '<暂存目录中沿用原名的文件绝对路径>'
```

`inspect` 只读；`clean` 必须指定不存在的新输出，且扩展名与原件一致。退出码 0 表示命令执行成功，2 表示未完成。JSON 只列属性名和复查类别，不打印原作者等值。不要因命令成功而忽略 `review_flags`。

直接支持：`.docx`、`.pptx`、`.xlsx`（包括 WPS 保存的这些格式）、普通 `.pdf`。

- OOXML：清空核心属性和自定义属性；删除 Application、AppVersion、Company、Manager、Template、TotalTime；重建 ZIP 清除 ZIP 注释、额外字段，内部条目时间归一化。不改变其他成员字节。内部 ZIP 时间归一化不是对文档年龄的证明。
- PDF：移除 Info 与可达对象上的 Metadata/XMP，完整重写并清除孤立对象，避免只做增量保存。保留正文、页面、表单与注释；这些对象可能仍有身份信息。
- 已签名、加密、PDF/A、PDF/UA 或超限文件不直接清理，按格式专门处理并说明未完成。不要通过删签名或改扩展名绕过拒绝。
- `.doc/.xls/.ppt`、`.wps/.et/.dps`、宏文件、ODF、RTF、HTML 等见[格式分流](references/formats.md)，不得假称脚本支持。

## 内容与兼容性

对于用户上传的已有文档，先保留原件并检查；自定义属性可能驱动 DOCPROPERTY 字段、模板或业务系统。清理这些属性前确认它们不承担所需功能；无法确定时说明取舍。对新生成的交付物默认不依赖这些属性。

用户明确要求保留署名、文档标题元数据、修订或业务属性时服从该要求；按“用户指定属性”及格式专用编辑方法执行。本技能脚本本身清空全部核心/自定义属性，不支持属性白名单，指定属性需在清理后另行写入。

不擅自接受/拒绝修订、删除可见署名、批注、备注、引用、版权文字、水印、来源凭证或内容认证信息。需要影响内容的改动时，先给出具体项目与影响，依据用户已授权范围执行。

网上查证的机制与适用限制见[来源说明](references/sources.md)。若需要修改脚本，执行本技能的全部测试：

```powershell
& '<Python绝对路径>' -m unittest discover -s '<skill绝对路径>/tests' -v
```

测试临时文件创建在当前工作目录，应从有写权限的工作目录运行。
